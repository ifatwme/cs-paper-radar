How the radar works

Coverage

Every day the pipeline asks the arXiv API for all papers first submitted in these categories (primary or cross-listed): {{ settings.arxiv_categories|join(', ') }}. The last {{ settings.update_lookback_days }} days are re-fetched on every run, because arXiv publishes a day's submissions only after its evening announcement and updates (new versions, acceptance notes) arrive later. Older days that are missing or were stored incompletely are repaired automatically.

The score

Each paper gets up to eight signals in [0, 1]; the score is their weighted mean. Every paper page shows the raw numbers, the signal values, and the evidence behind each one.

Fairness rules

  • Same age, same field. Citations, upvotes, stars, novelty and momentum are percentiles within the paper's cohort: papers of the same research area submitted in the same week. A theory paper is compared with theory papers of its week, never with ML papers that are cited ten times faster.
  • Missing is not zero. A signal is used for a cohort only if it carries information there (at least {{ (settings.signal_min_coverage*100)|round|int }}% of the cohort has a non-zero value). Otherwise it is dropped for the whole cohort and the other weights are rescaled. Each score shows how much of the weight was actually measured.
  • Verified over claimed. Venue from Semantic Scholar or a journal reference beats an acceptance note in the arXiv comment.
  • No prestige shortcuts. Author h-index, team size and number of cross-listed categories are shown for context but are not part of the score: they reward famous groups and are easy to game.
  • Scores mature. Evidence keeps arriving, so the last {{ settings.rescore_weeks }} weeks are re-scored on every update. Rankings of the current week are provisional; older weeks settle as citations accumulate.

Topics

A topic query is matched two ways: BM25 keyword search over titles and abstracts (the query words close together, falling back to all words anywhere), and semantic search with sentence embeddings ({{ settings.embedding_model }}, run locally). Results are fused by reciprocal rank. For the matching papers the radar shows:

  • What's new — the most recent matching papers.
  • Frontier — the highest frontier scores among clearly relevant papers in the window.
  • Emerging terms — phrases whose share of the topic's papers rose most compared with the preceding period (log-odds z-score).
  • Research directions — clusters of the topic's papers (spherical k-means on embeddings), labelled by their most distinctive phrases.
  • Trend — the topic's share of all CS/CE papers per week.

API

Everything on the site is available as JSON — see the interactive API docs. For example /api/weekly?n=20, /api/daily?date=YYYY-MM-DD&cat=cs.CR, /api/topic?q=network%20security.

Limits

  • The score combines measurable evidence; it does not read the paper. In the first days after submission there are few citations, so the newest week leans on venue, released artifacts, novelty and momentum.
  • Venue detection relies on what authors write in the arXiv comment field.
  • Days are UTC submission days, not arXiv announcement days.
